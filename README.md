# Parts Tracker

Track PC part prices across the shops PCPartPicker doesn't cover (mostly Portuguese, Spanish, French and UK merchants). Prices are scraped on a schedule or on demand, every observation is kept, and history is shown in interactive charts.

> Status: **milestone 6 — user features**. The full plan is in [docs/BUILD_PROMPT.md](docs/BUILD_PROMPT.md).

## Stack

| Layer    | Choice                                                                            |
| -------- | --------------------------------------------------------------------------------- |
| App      | Next.js 16 (App Router, Cache Components) + TypeScript, deployed on Vercel        |
| UI       | Tailwind CSS v4, shadcn/ui (Radix), lucide icons, next-themes (light/dark/system) |
| i18n     | next-intl — English at `/`, Portuguese at `/pt`                                   |
| Database | Turso (libSQL) + Drizzle ORM; local SQLite file                                   |
| Scraper  | Node/TS + Playwright (Chromium) in GitHub Actions                                 |
| Auth     | Better Auth (email/username + password), roles, invites, admin approval           |
| Tests    | Vitest                                                                            |

## Layout

```
apps/web          Next.js app
packages/core     pure parsing & matching logic, GTIN helpers (no I/O)
packages/db       Drizzle schema, libSQL client, migrations, seed & legacy import
packages/scraper  fetch/Playwright runner that matches offers and writes prices (GitHub Actions)
docs/             build prompt and design notes
```

## Database

Schema: `packages/db/src/schema.ts`. Migrations: `packages/db/drizzle` (generated by drizzle-kit, committed). Without env vars everything uses `local.db` at the repo root.

```bash
pnpm db:migrate         # apply migrations
pnpm db:seed            # app settings + the 12 merchants from the legacy app
pnpm db:generate        # after editing the schema: write a new migration
```

### Import the legacy data

Copy `pc_tracker.json` from the old Python app to `.scratch/pc_tracker.json` (gitignored; never commit it), then:

```bash
pnpm db:import-legacy   # or: pnpm db:import-legacy path/to/pc_tracker.json --owner <userId>
```

It imports merchants, products, GTIN/MPN/ASIN identifiers, manual and auto URLs, the last known status per shop, blocklists and the full price history. The components go into a "Legacy build" owned by the first admin, or by a banned `legacy-admin` placeholder user when no admin exists yet; `pnpm seed:admin` moves that data to the admin and deletes the placeholder. Re-running skips products that already exist, so history is never duplicated.

### Production database (Turso)

1. Install the Turso CLI and sign in: `turso auth login`.
2. Create the DB: `turso db create parts-tracker`, in a region close to Vercel's (e.g. `fra`).
3. Get the URL and a token: `turso db show parts-tracker --url` and `turso db tokens create parts-tracker`.
4. Put them in `apps/web/.env.local` as `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN`, then run `pnpm db:migrate`, `pnpm db:seed` and optionally `pnpm db:import-legacy`.
5. Add the same two variables in Vercel (`vercel env add`) and, for the scraper (milestone 4), as GitHub secrets (`gh secret set`). Paste the token into those commands yourself; never commit it.

## Scraper

`packages/scraper` checks every enabled (product, merchant) pair and writes the results:

1. A pinned URL (`product_merchant.manual_url`) is always used. The rules still run, and a disagreement shows up as a warning in `last_match`.
2. Otherwise the learned `auto_url` is revalidated. It is dropped after 3 runs in a row that don't match.
3. Otherwise the shop is searched by GTIN, then MPN, then the product's query. At Amazon shops a known ASIN is tried first (`/dp/<ASIN>`).

Pages are scored by the matching engine in `@parts/core` (see [docs/matching.md](docs/matching.md)):

- **Accept** appends a `price_points` row (EUR plus the original currency and shipping) and stores the URL as `auto_url`.
- **Review** writes a pending `match_candidates` row with the rule breakdown.
- **Reject** is only logged.

Each run writes `scrape_runs` and one `scrape_logs` row per pair: `ok`, `out_of_stock`, `not_found`, `blocked` or `error`, with timings and a truncated trace. FX rates come from the ECB daily file, cached in `fx_rates` for 6 h.

**Politeness:** plain `fetch` comes first, with a desktop Chrome UA and `Accept-Language: pt-PT`. Requests to one host are at least 1.5 s apart, with at most 2 in flight per shop, and 429/202 responses are retried with backoff. Playwright is used when the merchant has `needs_browser`, when a page needs JavaScript, or when the shop answers 403/429/202/503; its init script hides `navigator.webdriver`. The scraper never solves CAPTCHAs: if a shop still blocks, the pair is marked `blocked` and the run moves on. A merchant's `adapter_config.throttleMs`/`maxConcurrency` can slow a shop down further but never speed it up.

```bash
pnpm --filter @parts/scraper browser:install     # once: download Chromium for Playwright
pnpm scrape                                      # every enabled pair, into local.db (or Turso if set)
pnpm scrape --product <id|name> --merchant <id|slug|name>
pnpm scrape --no-browser                         # plain fetch only
```

The raw HTML of failed fetches goes to `debug/` (gitignored), and in Actions to the run's `scrape-debug-*` artifact. It is never stored in the DB.

### GitHub Actions

`.github/workflows/scrape.yml` runs on a cron schedule (`17 */6 * * *`, every 6 h) and on `workflow_dispatch` with the inputs `productId`, `merchantId` and `runId` (a `scrape_runs` row created by the web app; one is created when the input is empty). It needs two repo secrets. Paste the token into the command yourself:

```bash
gh secret set TURSO_DATABASE_URL
gh secret set TURSO_AUTH_TOKEN
```

Until both secrets are set, the job logs a warning and skips. Run it by hand with `gh workflow run scrape.yml -f productId=<id>`.

## Auth & admin

Sign-in is [Better Auth](https://www.better-auth.com) with its Drizzle adapter: **email or username plus password**. There's no email service in the sign-in path, so addresses aren't verified. Invites are redeemed only with their secret link, and the default `approval` mode has an admin vet each new account. A forgotten password is reset by an admin (Admin → Users → Set password).

**First admin.** Create it once per database. It asks for a password (not echoed); re-run it to change the password or username:

```bash
pnpm seed:admin --email you@example.com --username you
```

**Sign-up modes** (Admin → Users): `open` (anyone, active at once), `approval` (default: new accounts are `pending` until an admin approves them) and `invite_only`. An invite is a sign-up link valid for 7 days that skips approval and carries the role the admin chose. Admin → Users shows the link to copy, and it's also emailed when Resend is configured.

**Admin area** (`/admin`, reached from the account menu, never in the sidebar): users (approve, invite, role, set password, ban, sign out everywhere, delete, signup mode), merchants (CRUD, order, adapter editor, "Test merchant"), catalog identifiers, the review queue (Approve pins the URL and confirms the page's identifiers; Reject blocklists it) and the audit log of every admin change.

**Guards.** `requireAdmin()` (pages; anyone else gets a 404) and `adminAction(schema, handler)` (every admin Server Action) in `apps/web/src/lib/auth/guard.ts` re-check the session on the server. `admin-guard.test.ts` calls every admin action as anonymous, pending, banned and plain users and checks each is refused before touching the DB.

**Test merchant** dispatches `scrape.yml` for one (product, merchant) pair with a fine-grained token (`GH_DISPATCH_TOKEN`: this repo only, **Actions: read and write**), then polls the run. Without the token the page shows the equivalent `pnpm scrape` command to run locally.

**Production env (Vercel).** Only `BETTER_AUTH_SECRET` is required: `BETTER_AUTH_URL` and `GH_REPO` come from Vercel's system variables, and the Turso pair is already set. Run the script once to create the gitignored `apps/web/.env.vercel`, fill it in, then run it again to push it (`--dry-run` previews). You can also paste that file into Vercel → Settings → Environment Variables.

```bash
bash scripts/setup-vercel-env.sh
```

From PowerShell: `& "C:\Program Files\Git\bin\bash.exe" -lc "bash scripts/setup-vercel-env.sh"`.

## Builds & account

- **My builds** (`/builds`): each user's part lists with the current best price per part (cheapest in-stock offer among the shops they compare, optionally with shipping) and the total. Add parts by searching the catalog, pasting a shop link (only for known merchants; the link is never fetched by the server), or pasting a PCPartPicker list (Markdown or plain text, up to 40 parts). New parts join the shared catalog after deduplication by link, ASIN/GTIN and name.
- **Check now** queues a scrape of the build (scope `{buildId}`) on GitHub Actions. Users get one manual run per `userRunCooldownMinutes` (admins are exempt), and runs whose pairs were all checked within `recentCheckSkipMinutes` are refused because prices are shared.
- **Report wrong match** sends the pair's current offer to the admin review queue; only an admin's "Confirm wrong" blocklists it (and unpins the URL).
- **Share**: a public read-only page at `/share/<token>` (random token, can be reset), showing only the owner's display name.
- **Profile & settings** (`/account`): display name and username, email change (current password required), password change, active sessions, preferences (language, theme, default build, shipping in prices, which shops to compare), data export (JSON) and account deletion (password required; the last admin can't delete themselves).

## Translations

All UI text lives in `apps/web/messages/<locale>.json`; `en.json` is the source of truth and keys are type-checked. To add a language, add a JSON file with the same keys and register the locale in `apps/web/src/i18n/routing.ts`. A test fails if any locale is missing keys.

Import the GitHub repo in Vercel and set **Root Directory** to `apps/web` (Vercel detects pnpm workspaces). Environment variables are listed in [.env.example](.env.example).
